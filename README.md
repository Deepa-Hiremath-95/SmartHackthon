# NEXVION: Backend Data Model, Seeds & Live WebSocket Simulator

NEXVION conveyor belt joint health monitoring and predictive maintenance backend engine, built according to `AGENTS.md` and `docs/PRD.md` (Sections 5, 9, and 13).

> **DEMO / SIMULATION NOTICE:** All data generated by the simulator is explicitly marked `provenance: "SIMULATED"` and RUL is marked `status: "DEMO"`. The dashboard is advisory only and never starts or stops physical equipment.

---

## 1. Quick Start Guide

### Prerequisites
- Python 3.11+
- Windows PowerShell or command prompt (or Linux/macOS terminal)

### Setup Virtual Environment
If not already activated, create and activate the virtual environment:

**PowerShell (Windows):**
```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

**Linux / macOS:**
```bash
python3 -m venv .venv
source .venv/bin/activate
```

### Install Pinned Dependencies
```powershell
pip install -r backend/requirements.txt
```

---

## 2. Running the Server

Start the FastAPI application with Uvicorn:

```powershell
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --reload
```

On startup, the server automatically:
1. Creates the SQLite database tables (`nexvion.db`).
2. Seeds **2 conveyors** and **24 primary joints** (`CV-01` with `J01`–`J24`, plus `CV-02` with 6 joints).
3. Establishes commissioning baselines and inspection station sensors.
4. Starts the real-time simulation engine at the **600× demo preset** (so target joint `J04` progresses from Healthy to Critical in ~90 seconds).
5. Opens the live WebSocket stream at `ws://127.0.0.1:8000/ws/live`.

## 3. Running the Demo WebSocket Client

In a separate terminal window, run the command-line stream watcher:

```powershell
python scripts/watch_ws.py
```

### Default Output Mode:
By default, the client focuses on the degradation story:
- Rows for target joint **J04**
- **State changes** across all joints (e.g. `J04: HEALTHY -> WATCH`)
- **One conveyor summary** emitted per lap (after the last joint crosses)
- Active alerts and scenario events

### CLI Flags:
- `--target <ID>`: Target joint to track in default filtered mode (default: `J04`)
- `--verbose`: Print every joint pass across the conveyor
- `--ascii`: Force plain ASCII formatting (`[OK]`, `[WARN]`, `[MAINT]`, `[CRIT]`) without ANSI colors or unicode emoji
- `--count <N>`: Exit automatically after printing N messages (0 = run indefinitely)
- `--url <URL>`: WebSocket endpoint (default: `ws://127.0.0.1:8000/ws/live`)

## 4. Simulator Controls & Configuration

### REST Endpoints:
- **Engine Status:** `GET /api/v1/sim/status`
  Returns JSON with:
  ```json
  {
    "run_id": "run_20260921_153807_5ee9ab",
    "lap": 12,
    "speed_preset": "600x",
    "paused": false,
    "scenario_phase": "DEGRADING",
    "running": true,
    "conveyor_id": "CV-01",
    "time_acceleration": 600.0,
    "target_joint": "J04",
    "critical_laps_held": 0,
    "provenance": "SIMULATED"
  }
  ```
- **Speed presets:** `POST /api/v1/sim/speed?preset=600x` (supports `1x`, `10x`, `60x`, `600x`)
- **Pause:** `POST /api/v1/sim/pause`
- **Resume:** `POST /api/v1/sim/resume`
- **Reset:** `POST /api/v1/sim/reset`

### Environment Variables (`.env`):
- `SIM_SPEED_PRESET`: Default simulation speed (default: `600x`)
- `SIM_RANDOM_SEED`: Random seed for repeatable runs (default: `42`)
- `SIM_HOLD_CRITICAL_LAPS`: Number of laps J04 remains critical before holding/pausing (default: `15`)
- `SIM_AUTO_LOOP`: When `true`, automatically resets to lap 0 with a new `run_id` after critical hold (default: `false`)
- `SIM_MAX_STORED_EVENTS`: Maximum stored pass-events in SQLite before pruning excess records (default: `1000`)

## 5. Running the Automated Test Suite

Run the full test suite with `pytest`:

```powershell
python -m pytest -v
```

### Covered Test Areas (25 Tests):
1. `backend/tests/test_models_and_seeds.py`:
   - 2 conveyors (`CV-01` and `CV-02`), 24 joints on `CV-01` (`J01`–`J24`).
   - T1/T2 sensor capabilities on inspection stations.
   - Strict `Provenance` and `RULStatus` compliance.
2. `backend/tests/test_fusion_and_corroboration.py`:
   - **Corroboration rule:** Single-modality spikes stay at `WATCH` or below.
   - Multi-modal corroboration elevates state to `MAINTENANCE_REQUIRED` and `CRITICAL`.
   - Sensor-quality score down-weighting.
   - Persistence and hysteresis (3 of the last 5 passes for escalation; clear window for recovery).
   - **Trend-based RUL:**
     - Flat/healthy joints get `status: UNAVAILABLE` with `reason: "no_degradation_trend"`.
     - Degrading joints get `status: DEMO` with dynamically calculated time-to-threshold intervals.
   - Conveyor risk index formula: `0.6 * mean + 0.4 * worst`.
3. `backend/tests/test_scenario_and_simulator.py`:
   - Simulator produces **only** physical signals and vision detections (no hard-coded states).
   - **Scenario Plateau:** J04 degradation signals saturate at plausible maxima with fused health settling in the **20–35%** range (not near 0%).
   - **Once-per-lap conveyor summary:** Emitted after the 24th joint crosses.
   - **Critical hold laps & scenario event:** Emits `scenario_event` and pauses/resets when held for N laps.
   - **Run ID generation:** Each simulation run has a unique `run_id`.
   - **SQLite row capping:** Automatically prunes oldest pass events when exceeding max threshold.
   - Deterministic seed reproducibility and speed presets (`1x`, `10x`, `60x`, `600x`).
4. `backend/tests/test_api_and_websocket.py`:
   - REST API endpoints for assets, joints, and simulation status (`run_id`, `lap`, `speed_preset`, `paused`, `scenario_phase`).
   - WebSocket `/ws/live` connection, handshake acknowledgement, and ping/pong.
